# yaf NEWS

## 0.11.0

### Новое
- Функции записи: `yaf_add_campaigns()`, `yaf_add_adgroups()`,
  `yaf_add_keywords()`, `yaf_add_ads()`, `yaf_add_sitelinks()`,
  `yaf_add_adextensions()`, `yaf_moderate_ads()`, `yaf_suspend_campaigns()`,
  `yaf_resume_campaigns()`, `yaf_delete_campaigns()`. Возвращают таблицу
  `Id`, `Errors`, `Warnings` по объектам, батчи режутся автоматически.
- `yaf_api_add()` — метод `add` любого сервиса с батчами.
- `yaf_api_call()` — произвольный метод любого сервиса.
- Поддержка версии API `v501` (единые перфоманс-кампании): аргумент
  `version`. Кампании, группы и объявления по умолчанию создаются через
  `v501`: комбинаторные объявления (`ResponsiveAd`) `v5` не принимает.

### Изменения поведения
- Изменяющие запросы не повторяются при сетевой ошибке и HTTP 5xx, чтобы
  не создавать дубли. Временные ошибки API (52, 506, 1000–1002)
  повторяются, как и раньше.
- У всех функций появился необязательный аргумент `token`: токен можно
  передать явно, не читая RDS. Это нужно для серверных и параллельных
  запусков. При `token = NULL` поведение прежнее.
- У всех сетевых функций появился аргумент `timeout` (по умолчанию 60 секунд,
  переопределяется опцией `yaf.timeout` или переменной `YAF_TIMEOUT`).
  Раньше зависшее соединение могло заблокировать R-процесс навсегда.
- `yaf_get_report()` с пустым ответом (0 строк) возвращает пустую таблицу
  с запрошенными колонками, а не падает в `read.table()`.
- `yaf_get_ads()` разбирает `ResponsiveAd` (заголовки и тексты через `; `)
  и предупреждает о типах объявлений, содержимое которых не разобрано.

### Исправления
- Ошибка API без `error_code` больше не роняет разбор сообщением
  «argument is of length zero»: код считается неизвестным, текст ошибки
  сохраняется.
- Пагинация `yaf_api_get()` останавливается с `yaf_api_error`, если
  `LimitedBy` не растёт: раньше это могло зациклить запросы.
- `batch_ids` проверяются на `NA` и нечисловые значения до запроса.
- `yaf_ws_top()` пропускает неполные строки Wordstat (без `phrase` или
  `count`) с предупреждением, повторяет запрос при 429 с учётом
  `Retry-After` и не превышает 100 запросов за вызов.
- `yaf_get_regions()` использует общий транспорт: ретраи, таймаут и ошибки
  класса `yaf_api_error` вместо общего исключения httr2.
- `yaf_check_campaign_changes()` и `yaf_check_changes()` при отсутствии
  `Timestamp` в ответе оставляют исходный timestamp и предупреждают,
  а не сбрасывают точку отсчёта и не пропускают изменения.
- `yaf_get_campaigns()` при совпадении имён полей блока кампании и верхнего
  уровня отдаёт приоритет верхнему уровню, а не блоку.
- `yaf_get_bid_modifiers()` надёжнее отличает массив условий от одиночной
  корректировки и не выбрасывает строки без Id молча.
- `yaf_get_report()` проверяет порядок дат, числовые `goals` и предупреждает,
  если `attribution` передан без `goals`; предупреждает о возможном
  усечении отчёта на лимите строк; имя отчёта очищается от недопустимых
  символов логина.
- `yaf_strategy_learning_check()` пропускает кампании с неизвестным типом,
  а не падает на `x[[NA]]`.

### Безопасность
- Файл токена создаётся с правами `0600`, каталог — `0700`.
- `login` проверяется: пустые значения, `NA` и разделители пути запрещены.

### Инфраструктура
- GitHub Actions: `R-CMD-check` для push в `master` и pull request.
- `LICENSE` приведён к формату DCF, полный текст — в `LICENSE.md`.
- Из `Imports` убраны неиспользуемые `R6` и `stringi`; объявлены
  глобальные переменные и `utils`.

## 0.10.1

### Исправления
- `yaf_get_report()` опрашивает готовность отчёта не чаще раза в 10 секунд
  (или через `retryIn` из ответа API, если он больше): API Директа стал
  отклонять частые запросы ошибкой 56 «Превышен лимит запросов метода».
  Ошибка 56 больше не прерывает выгрузку, запрос повторяется.
  `max_tries` по умолчанию уменьшен с 600 до 120, чтобы ожидание осталось
  около 20 минут.
- `yaf_get_report()` при ошибке API показывает код и текст ошибки Яндекса
  (раньше httr2 прерывал запрос с общим «HTTP 400 Bad Request» / «HTTP 401
  Unauthorized»). При 401 и ошибке 53 подсказывает перевыпустить токен.
  Ошибки выбрасываются с классом `yaf_api_error`, сбои 502–504 повторяются.
- `yaf_get_report()` с одним полем в `fields` больше не падает: `FieldNames`
  всегда уходит массивом.

## 0.10.0

### Изменения поведения
- `yaf_ws_top()` переведена на новый API Wordstat из Yandex Search API
  (`searchapi.api.cloud.yandex.net/v2/wordstat/topRequests`). Вместо
  OAuth-токена `token` нужен API-ключ сервисного аккаунта (`api_key`,
  переменная `YANDEX_SEARCH_API_KEY`) и ID каталога (`folder_id`,
  переменная `YANDEX_FOLDER_ID`).
- Новый аргумент `devices`: `"all"`, `"desktop"`, `"phone"`, `"tablet"`.
- `region_id` принимает вектор регионов, `NULL` значит все регионы.
- Ошибки API Wordstat выбрасываются с классом `yaf_api_error`.
- При углублении фразы, совпадающие с исходными масками, не
  запрашиваются повторно, чтобы экономить часовую квоту (100 запросов).

## 0.9.0

### Новое
- `yaf_strategy_learning_check()` — оценка обучения стратегий: конверсии по
  целям стратегии за 7 дней против порога 10 (статусы `ok` / `low_data` /
  `not_applicable`). Цели берутся из стратегии кампании (`GoalId`,
  `PriorityGoals`), поиск и сети проверяются отдельно, пакетные стратегии
  получаются через сервис `strategies` и считаются по всем своим кампаниям.

## 0.8.0

### Новое
- `yaf_api_get()` — универсальный get-запрос к любому сервису API Директа:
  батчинг, пагинация, повторы при временных ошибках, учёт баллов (атрибут `units`).
- `yaf_get_keywords()` — выгрузка ключевых фраз, с разделением фразы и минус-слов
  и ставками `Bid`/`ContextBid` (в валюте аккаунта) и `StrategyPriority`.
- `yaf_get_negative_keyword_sets()` — выгрузка наборов минус-фраз
  (всех или по `ids`).
- Отслеживание изменений через сервис `changes`:
  `yaf_check_campaign_changes()` — какие кампании изменились и где
  (параметры кампании, дочерние объекты, статистика);
  `yaf_check_changes()` — id изменившихся кампаний, групп и объявлений,
  с батчами по лимитам API и перепроверкой необработанных объектов;
  `yaf_changes_timestamp()` — текущее время сервера для первого запуска.
- У `yaf_get_campaigns()`, `yaf_get_adgroups()`, `yaf_get_ads()`,
  `yaf_get_bid_modifiers()` появились аргументы `fields`/`type_fields`
  для выбора полей и `raw = TRUE` для получения сырого ответа API.
- `yaf_get_campaigns()` теперь проходит все страницы результата и по умолчанию
  выгружает стратегию (`BiddingStrategy`) для кампаний всех типов (текстовые,
  ЕПК, мобильные приложения, медийные), минус-слова кампании
  (`NegativeKeywords`) и id привязанных наборов минус-фраз.
- `yaf_get_bid_modifiers()` поддерживает корректировки для планшетов,
  десктопов, по типу выдачи и уровню дохода.
- `yaf_get_ads()` возвращает колонку `display_url_path`.

### Изменения поведения
- Ошибки API больше не пропускаются молча: функции останавливаются с ошибкой
  класса `yaf_api_error`. Раньше упавший батч пропускался, и функция
  возвращала неполные данные без предупреждения.
- `yaf_get_campaigns()` при ошибке вызывает `stop()` вместо возврата `NULL`.
- Новый формат таблицы `yaf_get_campaigns()`: поля из блоков `TextCampaign`,
  `UnifiedCampaign` и т. д. идут без префикса типа
  (`BiddingStrategy.Search.BiddingStrategyType` вместо
  `UnifiedCampaign.BiddingStrategy.Search.BiddingStrategyType`), списки
  склеены в одну колонку через `; ` вместо `Items1`, `Items2`…, числовые поля
  остаются числами, а не строками.
- В `yaf_get_adgroups()` с дополнительными `fields` вложенные поля
  разворачиваются так же, а не в JSON-строку.
- В неинтерактивной сессии (Rscript, cron) при отсутствии токена
  функции сразу останавливаются с понятной ошибкой, а не ждут ввода.

### Исправления
- У всех функций пакета есть справка: параметры, возвращаемое значение,
  примеры.
- `yaf_get_bid_modifiers()` падала на видео- и смарт-корректировках
  (вызов несуществующей `safe_extract()`).

## 0.4.0

### Изменения в yaf_get_report()

- Добавлен аргумент `attribution` для выбора моделей атрибуции (FC, LC, LSC и др.).
- Аргумент `include_vat` теперь явно логический и маппится в IncludeVAT = "YES"/"NO" в API.
- Добавлен аргумент `save_dir` для кастомного пути сохранения отчётов (по умолчанию "reports").
- Добавлен аргумент `max_tries` для ограничения числа попыток опроса отчёта, чтобы избежать бесконечного ожидания.
- Удалён устаревший аргумент `atribution` (используйте `attribution`).
- Улучшена валидация аргументов (`login`, `date_range_type`, `include_vat`, `save_report`, `save_dir`, `max_tries`).
